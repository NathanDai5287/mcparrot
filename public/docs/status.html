Status checked October 17, 2026

Reading the status words

Every feature on this page carries one of four status words. A feature is shipped only after a check proves that it works, so a plan never looks finished before it is. The other guides use the same four words when they mention status. If a feature has no proof yet, it stays aspirational, even when we know exactly how to build it.

The four status words
WordWhat it means for you
shippedYou can use it today, and a check has shown that it works.
dormantWe built it, but nothing in the product uses it yet.
aspirationalWe agreed on it or designed it, but we have not built it yet.
gapA known missing piece or problem inside something that is shipped.

What you can do

Today you can open the workspace, create website apps, explore any website with the browser extension, let Cursor Composer find what the site can do, and save the tools you choose. Each app page also lets you sign in once through Browser Use, save your login for the website, and copy a private link for ChatGPT, which runs your saved tools, can read any page on that website, and can save a useful page as a new tool. When a website signs you out, MCParrot signs in again with the saved login and asks you in ChatGPT for the text-message code. When you turn on an app’s Ordering switch, ChatGPT and the app page can prepare an order, show you the cart, and pay with Pay with Link, but only while Link is in test mode. On October 17, 2026, you connected ChatGPT to your Canvas app, and Canvas tools worked from ChatGPT. Your live tests of exploring, signing in, and signing in again automatically are still needed. Sentry now receives errors from the hosted website, and three of them led us to fix MCParrot. Timings, logs, and recordings from the hosted website are not confirmed yet. People now sign in to MCParrot with their own Google account, each person has their own apps, each app has its own secret ChatGPT link, and a public marketplace shares apps’ tools. These passed checks on our computer, but they need checks on the hosted website. Testing tools before they appear in ChatGPT is still aspirational. Known gaps today

Some shipped features have known missing pieces. These gaps do not stop you from trying the features, but they limit what each feature proves. We close each gap through the stage of work that needs it. The list below names every gap we know about.

  • gap Your live test of Sign in to website is still needed.
  • gap Automatic sign-in and the text-message code step have not met the real Canvas and Duo pages yet, so your live test must show that the agent finds the text-message option.
  • gap Browser Use keeps the waiting browser for 15 minutes only for paid accounts. Free accounts close it after 2 minutes, so type the code quickly or ask again.
  • gap An automatic sign-in that takes longer than 2.5 minutes ends with an error, because Vercel stops each call after 5 minutes.
  • gap ChatGPT first asks for the newest connection version, which no MCP toolkit supports yet. MCParrot relies on ChatGPT then using the older version, as it did in your ChatGPT test on October 17, 2026.
  • gap Saved tools appear in ChatGPT without a test and only read information. Some websites need special codes that only their own page adds, so some tools can fail.
  • gap ChatGPT can read any page your account can see on an app’s website, not only the tools you chose. You accepted this. It only opens pages, so it changes nothing unless just opening a page changes something on that website, such as a sign-out link.
  • gap Pages that fill in their content only after you click something can come back with part of their text missing.
  • gap ChatGPT saves new tools without asking you. You accepted this, so delete any tool you do not want on the app page.
  • gap Anyone with an app’s ChatGPT link can run that app’s tools, read its website’s pages with your sign-in, and save tools to it until you select Regenerate link.
  • gap While the Vercel sign-in stays on, your older ChatGPT links carry a secret that opens the whole website, and Vercel blocks the new links, so new links work only after you turn the Vercel sign-in off.
  • gap Your existing apps move into your account the first time you open MCParrot after this change. Until then, their ChatGPT connections stop working, so open MCParrot once right after it is published.
  • gap You chose no limits for other people, so their discovery spends your Cursor credit and their sign-ins and tools spend your Browser Use credit.
  • gap The extension and our website hide secrets in recorded answers and addresses only when they look like known kinds of secrets, such as long random codes or values named “token” or “password”. A secret in another form can still be kept and sent to Composer.
  • gap Your live test of exploring a website and finding what it can do is still needed.
  • gap Your live test of the “New” and “Updates” marks, saving an update, and reopening the last list is still needed. If you rename an update before you save it, it shows again in the last list until you find what the site can do again.
  • gap The extension needs one manual installation in Chrome or Edge. It is not in an extension store and does not update automatically.
  • gap Your agent can run saved tools and read pages but cannot do the workspace actions, and the workspace has no button to run a tool or read a page, so the workspace does not meet the rule of equal controls for agents.
  • gap Timings, logs, and recordings from the hosted website are not confirmed in Sentry yet.
  • gap Ordering has not met a real Browser Use run, Link connection, or website yet, so a live test must show that the agent fills the cart, reports it correctly, and checks the total.
  • gap You chose test mode only. DoorDash has no test mode, so a DoorDash order always stops when DoorDash declines the test Link card.
  • gap A card saved in your website account can still be charged if the agent ignores its instructions, so remove saved cards from the website account before you test ordering.
  • gap Orders do not sign in again by themselves. A signed-out app shows the message to sign in first.
  • gap The Browser Use key exists only for the production website, so preview websites cannot sign in, run tools, read the Link status, or place orders.

Order of remaining work

The remaining work happens in eight stages, and each stage ends with a demonstration that we check. The first stage proves that a recorded website tool can repeat with new inputs, not only that a browser can click through pages. Design polish and support for many kinds of tools come after that proof. A stage becomes shipped only when its check passes.

Aspirational stages, in order
StageWhat we buildHow we know it is finished
1. Discover and repeat one toolYou explore a reading page, let Cursor Composer find what the site can do, and choose one tool, such as listing assignments on a course site, then sign in once through Browser Use.The app repeats the tool with your saved sign-in, and the result matches the website.
2. Use it from an assistantYou add the app’s private link to ChatGPT.You ask ChatGPT for the tool with changed inputs and receive the correct result.
3. Find problems with SentryYour testing fills Sentry with errors, timings, logs, and recordings.We find and fix a real problem with the evidence that Sentry collected.
4. Test and enable toolsChosen tools get tests with changed values before they appear in ChatGPT.One session suggests several tools, and you test and reuse each enabled tool.
5. Recover expired sign-insA waiting tool survives an expired sign-in and your verification.You sign in again, and the waiting tool finishes once, without repeated effects.
6. Use a second websiteYou teach a tool on another website.The same product steps work without a design made only for that website.
7. Prepare the demoA demonstration of teaching, assistant use, and the problem that Sentry helped us fix.We complete the whole demonstration and explain its limits.
8. Share appsPeople sign in to MCParrot with their own accounts, then share an app with its tool steps.Another person reuses a shared app’s tools with their own sign-in.
