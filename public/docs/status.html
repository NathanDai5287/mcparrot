Reading the status words

Every feature on this page carries one of four status words. A feature is shipped only after a check proves that it works, so a plan never looks finished before it is. The other guides use the same four words when they mention status. If a feature has no proof yet, it stays aspirational, even when we know exactly how to build it.

The four status words
WordWhat it means for you
shippedYou can use it today, and a check has shown that it works.
dormantWe built it, but nothing in the product uses it yet.
aspirationalWe agreed on it or designed it, but we have not built it yet.
gapA known missing piece or problem inside something that is shipped.

What you can do

Today you can open the workspace, create website apps, explore any website with the browser extension, let Cursor Composer find what the site can do, and save the tasks you choose. Each app page also lets you sign in once through Browser Use, save your login for the website, and copy a private link for ChatGPT, which runs your saved tasks, can read any page on that website, and can save a useful page as a new task. When a website signs you out, MCParrot signs in again with the saved login and asks you in ChatGPT for the text-message code. Your live tests of exploring, signing in, signing in again automatically, and asking ChatGPT to run a task are still needed. Sentry is set up to collect errors, timings, logs, and recordings, but it needs your use of the hosted website. Testing tasks before they become tools is still aspirational. Known gaps today

Some shipped features have known missing pieces. These gaps do not stop you from trying the features, but they limit what each feature proves. We close each gap through the stage of work that needs it. The list below names every gap we know about.

  • gap You must finish the Upstash setup in Vercel before the production website can load your apps.
  • gap Your live tests of signing in and asking ChatGPT to run a task are still needed.
  • gap Automatic sign-in and the text-message code step have not met the real Canvas and Duo pages yet, so your live test must show that the agent finds the text-message option.
  • gap Browser Use keeps the waiting browser for 15 minutes only for paid accounts. Free accounts close it after 2 minutes, so type the code quickly or ask again.
  • gap An automatic sign-in that takes longer than 2.5 minutes ends with an error, because Vercel stops each call after 5 minutes.
  • gap ChatGPT first asks for the newest connection version, which no MCP toolkit supports yet. MCParrot relies on ChatGPT then using the older version, and your live ChatGPT test must confirm it.
  • gap Saved tasks become tools without a test and only read information. Some websites need special codes that only their own page adds, so some tasks can fail.
  • gap ChatGPT can read any page your account can see on an app’s website, not only the tasks you chose. You accepted this. It only opens pages, so it changes nothing unless just opening a page changes something on that website, such as a sign-out link.
  • gap Pages that fill in their content only after you click something can come back with part of their text missing.
  • gap ChatGPT saves new tasks without asking you. You accepted this, so delete any task you do not want on the app page.
  • gap Anyone with an app’s ChatGPT link can use the whole website until you make a new secret. They can see your apps and links, change apps, tasks, and logins, ask Composer for tasks, and open a live browser with an app’s sign-in.
  • gap The extension and our website hide secrets in recorded answers and addresses only when they look like known kinds of secrets, such as long random codes or values named “token” or “password”. A secret in another form can still be kept and sent to Composer.
  • gap Your live test of exploring a website and finding what it can do is still needed.
  • gap The extension needs one manual installation in Chrome or Edge. It is not in an extension store and does not update automatically.
  • gap Your agent can run saved tasks and read pages but cannot do the workspace actions, and the workspace has no button to run a task or read a page, so the workspace does not meet the rule of equal controls for agents.
  • gap Sentry has not yet received reports from the hosted website, and no Sentry evidence has changed MCParrot yet.

Order of remaining work

The remaining work happens in seven stages, and each stage ends with a demonstration that we check. The first stage proves that a recorded website task can repeat with new inputs, not only that a browser can click through pages. Design polish and support for many kinds of tasks come after that proof. A stage becomes shipped only when its check passes.

Aspirational stages, in order
StageWhat we buildHow we know it is finished
1. Discover and repeat one taskYou explore a reading page, let Cursor Composer find what the site can do, and choose one task, such as listing assignments on a course site, then sign in once through Browser Use.The app repeats the task with your saved sign-in, and the result matches the website.
2. Use it from an assistantYou add the app’s private link to ChatGPT.You ask ChatGPT for the task with changed inputs and receive the correct result.
3. Find problems with SentryYour testing fills Sentry with errors, timings, logs, and recordings.We find and fix a real problem with the evidence that Sentry collected.
4. Test and enable tasksChosen tasks get tests with changed values and become tools.One session suggests several tasks, and you test and reuse each enabled task.
5. Recover expired sign-insA waiting task survives an expired sign-in and your verification.You sign in again, and the waiting task finishes once, without repeated effects.
6. Use a second websiteYou teach a task on another website.The same product steps work without a design made only for that website.
7. Prepare the demoA demonstration of teaching, assistant use, and the problem that Sentry helped us fix.We complete the whole demonstration and explain its limits.
