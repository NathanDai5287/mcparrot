MCParrot: Your Personal Web Agent

This page holds the text MCParrot submits on Devpost.

MCParrot is a personal agent that uses the websites you already sign in to, so ChatGPT can get things done there for you. It is built on Browser Use, which gives the agent real cloud browsers that sign in as you, read pages as you, sign back in when a website forgets you, and pay at checkout when you approve. You teach MCParrot a website once by browsing it normally, and from then on you can ask ChatGPT for your syllabus, your grades, or tonight's dinner order. No website has to offer an official API (a doorway built for other programs), and you never write code. We built it for the LA Hacks Applied Intelligence track, with Best Use of Browser Use as our main company challenge and Best Use of Sentry alongside it.

The Problem We Solve

Every student knows the Canvas shuffle. You want one fact, like when the next problem set is due, so you sign in, click the course, click Assignments, scroll, and squint. ChatGPT would happily do this for you, but it cannot get into your account, and Canvas offers it no doorway. The same is true for Gradescope, for school portals, and for the food site where you order the same burrito every Tuesday. What these sites need is not a new API but an agent with a real browser, your sign-in, and good manners, and that is exactly what Browser Use makes possible.

Browser Use Does the Work

Inside MCParrot, Browser Use is the part that actually touches the web. MCParrot decides what should happen, and Browser Use's cloud browsers and agents make it happen on the real website. Each app gets its own Browser Use browser profile, which works like a personal browser that keeps that website's cookies between visits. Browser Use's built-in stealth, home-internet proxies, and automatic CAPTCHA solving keep these browsers looking like an ordinary person. Browser Use does four separate jobs:

  1. It opens a live browser where you sign in to the website once.
  2. It runs every ChatGPT request in a hidden browser that is still signed in as you.
  3. It runs an agent that signs you back in when the website signs you out.
  4. It runs an agent that checks out and pays with Pay with Link after you approve.

Signing In Once

Signing in is the moment where most automation gives up, so MCParrot hands it to a person and a real browser. When you select Sign in to website, MCParrot starts a Browser Use cloud browser on the app's profile and opens Browser Use's live view in a small window. You sign in exactly as you normally would, including Duo prompts, text-message codes, or "Continue with Google". When you select Done signing in, the browser closes, and the profile keeps your session for next time. MCParrot stores only the profile's ID, never the cookies themselves, so your session stays inside Browser Use.

Running Every Tool

Each tool MCParrot saves is a small, named job, such as "List assignments in a course" or "Read the syllabus". When ChatGPT calls one, MCParrot starts a hidden Browser Use browser on your profile and connects to it with Playwright, a library that controls a browser through code. The tool then asks the website for its data from inside your signed-in page, exactly as the page itself would, and returns the answer to ChatGPT. For whole pages, such as a Canvas syllabus, a read_page tool opens the page and returns its visible text. Every tool stays on the app's own website, gives up after 30 seconds, and closes its browser when it is done.

Staying Signed In

Websites sign people out all the time, and a personal agent should not need a babysitter. When a tool finds the website signed out, MCParrot starts a Browser Use agent on the same profile and gives it your saved login as secret bindings. These are values the agent can type only into the website's own sign-in pages, without ever seeing them in its instructions. If the website texts you a code, the agent waits in its browser, ChatGPT asks you for the code in the chat, and a second agent run types it in and finishes. The agent never tries a rejected password twice, runs only one sign-in at a time for each app, and takes a ten-minute break after a failure.

An Agent That Pays

Reading your syllabus is nice, but the real test of a personal agent is whether it can buy you dinner. On shopping and food sites, a Browser Use agent fills the cart on your signed-in profile and stops at checkout. ChatGPT then shows you the items, fees, tip, and total before anything happens. Only after you approve does a second agent run pay with Browser Use's Pay with Link, which gives the agent a one-time card for that single purchase, so your real card number never reaches the agent or MCParrot. MCParrot's server also refuses to pay above your spending limit, if the total changed after you approved, or whenever Link is not in test mode, so every order in this version is safely pretend.

Teaching a New Website

Before the agent can work a website, MCParrot has to learn what that website can do. A small browser extension called MCParrot Explorer records the pages you open and what they ask the website's server for, with short samples of each answer. It skips passwords, cookies, and sign-in pages, and it blanks out anything that looks like a secret. Claude Opus 5.5, reached through the Cursor SDK, reads that recording and suggests tools, and you keep the ones you want. ChatGPT can also save a new tool on its own when it finds a useful page that no tool covers yet.

Sharing Through the Marketplace

Once one person has taught MCParrot a website, nobody else should have to start from scratch. The public marketplace lets you publish an app's tools, so anyone can add them to their own account with one click. A published app shares only its name, its website address, a short description, and its tool definitions. Your logins, your Browser Use profile, your recordings, and your private ChatGPT link never leave your account. Each person still signs in to the website through their own Browser Use browser, because a shared tool is a recipe, not a key.

Where Sentry Helped

Sentry is our flight recorder, and it earned its keep on the very first night. MCParrot sends it errors, traces that time each Browser Use step and website request, logs of every tool result, recordings of dashboard sessions, and monitoring of the AI agent. Sentry caught three real failures on the live site, and each one now has a fix in the code. The cloud server could not find a Playwright file, the Cursor SDK tried to write to a folder it was not allowed to touch, and ChatGPT spoke a newer protocol version than our library knew. Sentry also strips the secret part of every ChatGPT link before saving anything, so the recorder never holds the keys.

Tracks and Challenges

Our main company challenge is Best Use of Browser Use. Browser Use powers every moment where MCParrot meets a real website: signing in, running tools, signing back in, and paying. Our primary track is Applied Intelligence, because a personal web agent removes a chore people repeat every day. For Best Use of Sentry, we use error monitoring with Tracing, Logs, Session Replay, and AI agent monitoring, and Sentry evidence directly changed what we built. Every claim in this submission matches our public status page, which separates what works today from what is still being proven.

What Comes Next

A few Browser Use features are built but still waiting for their first live proof. Ordering needs one complete purchase with Link in test mode, and then a first real DoorDash order. Signing back in with "Continue with Google" reuses the Google session that stays in the Browser Use profile, so the agent never needs a Google password, and it is being built right now. After that, we want tools that can change things on a website, not just read them, and a way for ChatGPT to set up new apps by itself.

Built With and Links

MCParrot is built with Browser Use Cloud, Pay with Link, Playwright, Next.js, React, TypeScript, Vercel, Clerk, Upstash Redis, the Model Context Protocol, the Cursor SDK, Claude Opus 5.5, Sentry, and a Chrome extension. The live MCParrot app is open to anyone with a Google account, and the public marketplace works without signing in. The MCParrot source code on GitHub includes the full product specification and the status page, and the plain-language product guide explains every feature without code.
