What exists today

You can open the hosted workspace today and create website apps with draft tasks, which is shipped. Teaching real tasks and using them from your assistant are aspirational, so the rest of this guide describes the finished experience. The status page lists every feature with its status, the known gaps, and the order of the remaining work.

Where the app runs

The website has a Vercel project on the existing free Hobby plan. It is connected to our public GitHub repository. Updates to the main version publish to the production website, and other branches receive preview links. The status page records which of the parts below run today.

The complete product needs these parts
PartWhere it runs
Website and short server workVercel
Saved apps, tasks, and progressA hosted PostgreSQL database, such as Supabase or Neon
Teaching and hidden website browsersBrowser Use Cloud, with a private hosted recorder

A hidden browser must stay available while you complete phone verification. Vercel handles short requests, so that browser needs a separate host. Passwords, browser profiles, and private website content stay outside the public deployment. These guides are part of the website too.

How the product works

You create an app for one website, browse its pages, and review several suggested tasks from that session. Your assistant, such as ChatGPT, then uses all the tasks of a website app through one MCP connection. MCP is a standard way for an assistant to find and use the tools that you saved in another app, and each task you test and enable becomes one of those tools. Canvas, the course website of your school, is our first example, but the product is intended for many websites.

During teaching, also called parroting, a visible browser window opens so you can sign in and browse the pages yourself. During later assistant use, no visible website browser opens. The app uses saved website requests where supported and a hidden browser for steps that need one. You enter any supported sign-in recovery details or verification codes inside our app. The teaching window’s hosting method still needs proof.

Navigate your workspace

Opening an app or task changes its address, so browser Back and Forward work. Apps and draft names stay in this browser after a refresh. Select Delete app inside an app and confirm on the page to remove it and its drafts. This does not delete your school account.

Teaching must run through this website without a local helper. For the private Canvas pilot, sign in with your Vercel account and select Explore website inside the app, then Connect Canvas. You do not need to name a task first. A separate Canvas window opens. Sign in there, then return to MCParrot and select Start exploring. Browse course reading pages in the Canvas window, then return to MCParrot and select Review suggested actions. Review the captured reading requests together and select each one to test. Select Continue exploring to visit more pages without removing earlier captures. Select Open Canvas window to return to the same session. If the window is blocked, allow popups for MCParrot and try again. You do not need to install or start anything on your computer. Earlier local recordings are unavailable after their helper stopped. Sessions end after 30 minutes. Reopening exploration in this browser restores its session during that time. Older task links and their separate sessions still work. Ending the session deletes its captures; stopping recording keeps them for review. Reading tests show a count or a syllabus check, without opening another website window. See the status guide for the remaining cloud proof gap.

Continue Canvas sign-in

Connecting Canvas attempts your saved private sign-in once. For an existing session, select Sign in automatically or Check sign-in. If Berkeley offers a text code for your phone ending in 2199, MCParrot requests it once and shows a code box on the task page. Enter your code there and select Submit code. Do not send the code in chat.

MCParrot never approves your phone check for you. If the school rejects your password or offers another method, continue manually in the same Canvas window. Select Check sign-in afterward. When Canvas is connected, select Start recording. This automatic school flow still needs your production test; see the status guide.

Your private sign-in details and text code never go to an AI model or recording. The code leaves the form after submission and is not saved. Your existing teaching browser and observed requests stay in place.

Teaching a website task

This teaching experience is aspirational. The private hosted pilot still needs your live sign-in, recording, and reading test. Broader task suggestions and saved assistant tools also need more work.

  1. Create your app

    Visit our website, select Create app, and enter the website address. For example, name the app “Canvas.”

  2. Explore the website

    Select Explore website. Connect the visible teaching browser window. No task-name form is required. You can list desired actions in the optional notes area. Notes stay in this browser and do not create working tools.

  3. Sign in yourself

    Sign in to your school account in that window. Complete Duo or any other verification that the school requires.

  4. Browse while recording

    Start recording, then browse the pages you want the app to understand. For Canvas, you could visit assignments, announcements, and course materials in one session.

  5. Review suggested actions

    Select Review suggested actions to see the observed reading requests together. Select Continue exploring to add more pages. The pilot labels captured requests; it does not yet group them into complete tasks. Full task review remains aspirational.

  6. Test and enable tools

    Test each task with different inputs and compare its result with the website. Enable only the tools whose tests pass.

  7. Explore more when needed

    One session can suggest several tasks without repeating the same navigation. Record another session when you need features that were not discovered and tested.

You are the teacher

You browse pages once, then choose which suggested tasks to keep. Browser Use gives the browser access and can later help with sign-in. Suggestions are not usable tools until their tests pass. The first milestone only reads information. The app must not explore actions that change website data automatically.

Using your assistant

This experience after you teach a task is aspirational.

  1. Connect once

    Add the MCP address of your app to a compatible assistant, such as ChatGPT where it is supported.

  2. Ask for a result

    “Find my assignments due this week.”

    Your assistant chooses an enabled tool and supplies its inputs.

  3. Get the result

    The app repeats the saved website messages with your active login. Your assistant receives the result, and nobody needs to click through the website pages again.

Your assistant can combine enabled tools to answer new requests. One browsing session can expose several reading requests, but it cannot prove support for every website feature. Your desired-action notes are requests for future discovery, not proof that those actions work. An unsupported action needs more discovery and testing. Some actions may still need a hidden browser, and we must test those steps before we enable their tools. Assistant use must never open a visible website browser window.

Two kinds of connections

Each website app will get its own connection, and MCParrot will get a separate management connection. Both kinds are aspirational.

Choose what your assistant can access
ConnectionWhat you can ask your assistant to do
MCParrotCreate website apps, manage tasks, start teaching, check progress, and request sign-in recovery.
CanvasRun the verified tasks you taught inside your Canvas app.
YouTubeRun the verified tasks you taught inside your YouTube app.

For example, a Canvas app and a YouTube app give you two website connections, and the management connection makes three in total. Each website connection includes all the enabled tasks of that app, so you do not connect each task separately. You need the management connection only if you want your assistant to manage MCParrot for you. All connections come from our one hosted website.

  1. Choose a connection

    Open the connection details of the website app, or choose MCParrot management.

  2. Add it to your assistant

    Copy its address and follow the setup instructions for your compatible assistant.

  3. Authorize access

    Sign in and approve access to your own apps and tasks. The available connection options depend on your assistant.

Equal controls for agents

Your agent is your assistant when it acts for you. Everything you can do in MCParrot must also be possible through your agent. For example, you can create a Canvas app yourself, or you can ask your agent to create it with the same details. Both paths must give the same information and respect the same permissions. This rule covers actions and information, not the screen layout or moving between tabs.

The rule applies to app management, task teaching, testing, connections, progress, and recovery as those features become available. We check both paths before we mark a feature shipped. Today, the workspace has no agent connection, which is a gap listed on the status page.

You still control personal verification

Your agent could start a teaching session and give you a secure browser link. You could demonstrate the task there, or let an authorized agent operate the same session where this is supported. You still approve Duo on your phone and complete any other personal verification. After that, your agent checks progress and continues the supported work. Keep passwords and verification codes out of assistant messages.

Recovering an expired sign-in

A saved login can expire, and your task then needs a new sign-in. This recovery experience is aspirational.

  1. The browser attempts sign-in

    If you chose to save your sign-in details securely, Browser Use enters them and continues as far as possible. If not, you enter your sign-in details through a secure page inside our app.

  2. Your assistant shows a verification request

    The tool gives a Verification required status and a link that your assistant can show you.

  3. You complete verification

    Enter a verification code on the secure page, or approve Duo on your phone. Keep passwords and verification codes out of assistant messages.

  4. The task continues

    The browser finishes sign-in, and the app tries to continue the waiting task. Some assistants may need to check the task status before they show the result.

Needs a real school test

The sign-in rules of a school may prevent parts of this flow. Unsupported recovery must show a clear failure instead of opening a visible website browser. We have not tested automatic sign-in or Duo recovery on the website of your school.

Questions that need proof

  • Suggested tasks must pass a test with different inputs before your assistant can use them.
  • Pages you never visited remain unsupported unless discovered and tested separately.
  • Some pages return a whole document instead of separate data messages, so their tasks need another tested method.
  • Some website messages may work only inside the original browser.
  • A changed website may need another recording.
  • We must measure speed before we say the product is faster.
  • The first milestone only reads information. Actions that change website data need a separate plan.

Our first build milestone

First, you browse a reading page, review one suggested task, and test it with different inputs against the website. The order of remaining work lists every later stage and how we know each one is finished.

Make failures useful

Sentry is a service that reports errors and slow steps in an app. We intend to use its error reports, Tracing, and Logs to find failed or slow tasks. The demonstration should show a real problem that these tools helped us fix.
