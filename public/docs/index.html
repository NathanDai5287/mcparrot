How the product works

You create an app for one website, browse its pages, and review several suggested tools from that session. Your assistant, such as ChatGPT, then uses all the tools of a website app through one MCP connection. MCP is a standard way for an assistant to find and use the tools that you saved in another app, and ChatGPT sees each saved tool there. The product is intended for many websites, not one fixed example. You chose the word “tools” on October 17, 2026 for what you save and ChatGPT runs. The code and the names ChatGPT uses behind the scenes, such as save_task, still say “task”, so ChatGPT connections you already added keep working.

During teaching, also called parroting, MCParrot Explorer records the pages you open and the data requests they make in a normal Chrome or Edge tab. Exploration does not use a cloud browser. You then sign in once in a Browser Use cloud browser that you see in a popup. During later assistant use, no visible website browser opens: each tool runs in a hidden Browser Use browser that keeps your sign-in.

Teaching a website tool

Teaching has three steps: explore, discover, and choose. Finding what a site can do and choosing tools are shipped, but exploring is a gap until your live test of the extension passes. Testing tools before they appear in ChatGPT is aspirational. These steps work for any website, not only course sites.

  1. Create your app

    Visit our website, select Create app, and enter the website address. For example, name the app after the site you use.

  2. Install the extension once

    Select Explore website. Download MCParrot Explorer and extract its ZIP. Open your browser’s Extensions page, enable Developer mode, select Load unpacked, and choose the extracted folder. Reload MCParrot. It works in Chrome and Edge and is not in an extension store. To update it, remove the old copy first, then load the new folder. The current version is 0.5.0; version 0.4.0 does not keep what a website sends, so load 0.5.0 and explore again to get tools that send data, such as a DoorDash store search.

  3. Explore the website

    Select Open website and explore. A normal tab opens at the app’s website address. Sign in as usual and complete Duo or any other check. Browse the pages and features you want your assistant to use. Return to MCParrot and select Stop exploring.

  4. Find what the site can do

    Select Find what this site can do. Claude reads the recorded requests and the tools you already saved, and returns a list of things your assistant could do, such as listing assignments. When one request you made used a value from an earlier answer, such as a cart number, Claude is told to keep both requests in one tool so the value is passed along. For each tool that returns data, Claude also picks the parts of the answer that a person needs for that tool, such as titles, names, text, dates, scores, prices, and the numbers that other tools need, such as a thread number. It leaves out what your saved tools already do, but it can offer an update that adds these answer parts to a saved tool that has none. Each item shows what it does, which values you can change, and what it returns. Each item is marked “New”, or “Updates” and a tool’s name when it is a clearly better version of a tool you saved. MCParrot keeps the last list with its time, so when you come back to this page you see it again without a new paid run. Select Find what this site can do again when you want a new list.

  5. Choose your tools

    Tick the items you want, change their names or descriptions if you like, and select the save button, which shows how many you ticked, such as Save 3 tools. Saving adds the new ones to the app’s current tools and skips any you already have with the same name or the same requests in the same order, so tools ChatGPT saved stay. Saving an update replaces the tool it names and keeps it in the same place. Items you saved disappear from the last list. If you rename an update before you save it, it shows again until the next new list. The app page lists them, each with a Delete button. Each saved tool appears in the app’s ChatGPT connection right away. Select a tool on the app page to see each of its requests, numbered Step 1, Step 2, and so on, with its type, GET to read or POST to send data, its address, and any data it sends. Its Answer fields list the parts of the answer that ChatGPT gets, or say All.

  6. Explore more when needed

    Select Continue exploring to add pages without losing earlier requests. Then find what the site can do again and choose again.

You are the teacher

You browse pages once, then choose which suggested tools to keep. Claude’s list is a set of guesses from one visit, so a saved tool can fail when ChatGPT runs it. A test with changed values before a tool appears in ChatGPT is aspirational. Claude can suggest tools that send data, but never one that looks like checkout or payment, and finding tools never sends anything to the website.

What the extension records

The extension records only in the tab it opens for you. While it records, your browser shows a bar that says MCParrot Explorer is debugging the browser. It keeps each data request the page makes: its type, its full address, whether it worked, the kind of answer, and a sample of that answer. Long text is cut to 400 characters, lists keep 5 items, and each sample stays under about 12,000 characters.

You chose to also record each whole page you open, such as a course syllabus, because some pages arrive in one piece and never make a separate data request. For a page, the extension keeps its address, whether it worked, and the first 8,000 characters of the text you see on it, not the page’s code. Claude can then suggest tools that read a page, such as “Read course syllabus” for any course.

It skips pictures, fonts, styles, scripts, and media. It skips common tracking services and real sign-in pages, whose address has a word such as “login”, “logout”, “signin”, “password”, “oauth”, “sso”, “mfa”, or “2fa”. Words such as “auth”, “token”, “session”, “refresh”, and “verify” do not count, so it keeps addresses such as “/api/auth/me” and chat pages such as “chat_session”. It never copies cookies, the “authorization” label’s value, or a hidden sign-in code. Some websites, such as Ed, attach a hidden sign-in code to each request and keep that code in the browser’s own storage. When the extension sees such a code, it writes down only the code’s label and where the browser keeps it, such as “x-token” from “authToken”, and never the code itself, because saved tools can be shared on the marketplace. It also finds a code that starts with a word such as “Bearer”, and a code inside a stored group of values, and it writes down that word and where in the group the code is. Since version 0.8.0, it keeps every other label that the page sends with a request, such as a website’s app version or a session number, so tools on websites such as LinkedIn, GitHub, Instacart, and Notion work. It still leaves out labels with a secret name, such as “x-csrf-token” or “x-api-key”, labels whose value looks like a sign-in code, and labels that the browser sets by itself, such as the website address or the browser name. For requests that send data to the website, such as DoorDash’s store search, it keeps what your browser sent, up to 30,000 characters, so a whole GraphQL question fits. It writes “redacted” only in place of values named like “token”, “password”, “secret”, “api_key”, “cookie”, or “authorization”, and in place of sign-in codes that start with “Bearer” or “Basic” or have the shape of a JWT, a common kind of sign-in code. It keeps session numbers, such as “sessionId”, and long random codes, such as file numbers, order numbers, and GraphQL question fingerprints. You chose these rules on October 18, 2026, because AI tools may see anything on the website, while cookies and sign-in codes never go into a saved tool. If you used an older version, load version 0.8.0, explore again, and find tools again. It finds secrets only by these patterns, so a secret in another form can still be kept. Similar requests and pages are kept once, up to 150 for each app.

Recording stops when you select Stop exploring, close the tab, close the debugging bar, or restart the browser. Recorded requests stay in the extension until you select Delete recorded requests, delete the app, or remove the extension. The extension also deletes a recording 30 days after its last request. The extension only asks your browser for permission to store data without a size limit and to watch the tab it opens, not to read every website. Apps keep stable addresses, so Back and Forward work. The extension works with the production website and with the local test website on your computer.

What Claude sees

When you select Find what this site can do, our website sends the recorded requests and pages and their samples to Claude Opus 5.5 through the Cursor SDK, together with the app’s saved tools, which our website reads from its own storage. You chose this model on October 17, 2026, set to think briefly and answer quickly. Claude has its tools turned off and works in an empty folder that is deleted afterwards, so it cannot read our project files, and it only replies with the list of tools. Our website hides secret-looking values a second time before it sends anything, and it tells Claude never to follow instructions inside the recording. It also sends what each request sent to the website, with secrets hidden again. Claude is told to skip tracking and advertising requests and to prefer requests that read. It keeps only suggested tools on the website’s own domain, such as us.edstem.org for edstem.org, or spotify.com and api-partner.spotify.com for open.spotify.com, that read (GET) or send data (POST) and that do not look like checkout or payment. You chose real samples because they help Claude make better suggestions, and on October 18, 2026, you chose longer samples so Claude sees more of each answer. When a recording has many requests, our website shortens each sample so that everything fits for Claude, and when a recording is too large to send, the page sends only the newest requests. Sending website content to the AI is fine, including pictures that “Read an image on” and View image send to Claude; only secrets stay out. A picture on another website opens without your sign-in, so that website sees only the picture address, not your cookies or codes. Nothing goes to Claude until you select that button, and no passwords, cookies, request labels, sign-in codes, or sign-in pages are included, although a secret in a form that our patterns miss can still reach Claude.

Only you, or someone with an app’s private ChatGPT link, can use this feature, because Vercel asks everyone else to sign in before they can open the website. If Claude is not set up, does not start, does not finish within 50 seconds, or the recording is too large, the page shows a clear error message.

Signing in once

Your assistant needs your website sign-in to read your information. You chose to sign in once in a Browser Use cloud browser that remembers the sign-in for that app. This step is a gap until your live test passes. Your normal browser and this cloud browser have separate sign-ins, so signing in while you explore does not count.

  1. Start sign-in

    Open the app page and select Sign in to website. A popup opens with a cloud browser at the website. If your browser blocks the popup, select Open the sign-in window.

  2. Sign in

    Sign in as usual in the popup and complete Duo or any other check. You have 15 minutes.

  3. Finish

    Return to MCParrot and select Done signing in. The cloud browser closes and saves your sign-in. The app page and app list then show that the app is signed in.

You can also save your login on the app page, so MCParrot signs in again by itself when the website signs you out. Recovering an expired sign-in explains how.

Connecting ChatGPT

Each website app gets its own private connection link, which gives ChatGPT that app’s tools. This link is a gap until your live ChatGPT test passes. You chose to build only these app connections first. A separate MCParrot connection that would let ChatGPT manage your apps is aspirational.

Tools that read or send data appear in ChatGPT, and each one gets a ChatGPT name made from its own name. ChatGPT is told that a tool which only reads cannot change anything, and that a tool which sends data can change things on the website but does not delete them. Give every tool in an app a clearly different name. Changing only capitals, spaces, or punctuation does not count, so “Read Course” and “Read-Course” get the same tool name. Do not name a tool after a built-in tool, such as “Read page”, “View image”, “Save task”, “Submit verification code”, or one of the ordering tools, such as “Place order”. Each tool in a connection needs its own name, so MCParrot does not save a tool with such a name. If two older tools still share a name, ChatGPT sees the second one with a short code added to its name.

Each connection also has a tool called “Read a page on” your app’s name. ChatGPT gives it a page address on that website, such as a syllabus link you paste, and MCParrot opens the page with your saved sign-in in a hidden browser and returns its text. It refuses addresses on any other website. It uses the same length limit and the same sign-in recovery as tools. You chose this trade-off: ChatGPT can read any page your account can see on that website, not only the tools you chose. It only opens pages, so it changes nothing unless just opening a page changes something on that website, such as a sign-out link.

Each connection also has a tool called “Read an image on” your app’s name. You asked for it because an Ed announcement showed the class’s score average and spread only inside a picture. ChatGPT cannot look at pictures that a connection sends, so MCParrot looks for it: it opens the picture with your saved sign-in in a hidden browser, shrinks it, and asks Claude Opus 5.5, the same AI that finds tools, to copy every word and number in it and briefly describe any chart. ChatGPT gets only that text. ChatGPT is told to use this tool only when a picture likely holds something you need, such as a chart, a score distribution, or a screenshot, and to read one picture at a time, so pictures do not fill up the chat. It accepts PNG, JPEG, WebP, and GIF pictures and refuses anything else with a plain message. A picture on the app’s website domain, such as static.us.edstem.org for edstem.org, opens with your saved sign-in. Many websites keep pictures on a separate picture server, such as static.us.edusercontent.com for Ed, so you allowed this tool, and only this tool, to open a picture on any other website whose address starts with https. It opens such a picture in an empty part of the hidden browser, without your sign-in, cookies, or other saved codes, and it refuses an address that starts with http instead. Claude is told never to follow instructions written inside a picture. The app page has the same feature in its View image box: paste a picture’s address and select View image to see the picture and the same text. This feature is a gap until your live test on Ed passes.

Each connection also has a tool called “Save a tool for” your app’s name, so your connection grows while you use it. When ChatGPT finds something useful with the page reader, such as your syllabus, it saves that page as a tool and swaps values that change, such as the course number, for blanks it can fill next time. It can also choose the answer fields of the tool. It can also save one request that sends data, such as a search, and requests that run before it when that request needs a value from an earlier answer, such as a cart number. It refuses pages on other websites, anything that looks like checkout or payment, blanks without a matching value, a blank that points to a later request, and tools whose name or requests you already have. The tool appears on the app page, and ChatGPT can use it when you start a new chat. You chose to let ChatGPT save tools without asking you first, so delete any tool you do not want on the app page. Every change you make on the app page only touches that one app or tool, so a page you opened earlier never removes a tool ChatGPT saved.

  1. Create the link

    On the app page, select Create link, then Copy link. MCParrot shows the link only once. If you lose it, select Regenerate link, and the old link stops working.

  2. Open the plugin directory

    In ChatGPT, open Settings, then Plugins, and select Browse directory.

  3. Add the server

    Select Add, then Add custom MCP server. Name it after your app, paste the link as the Server URL, set Authentication to No authentication, tick the risk notice, and select Create as a plugin.

  4. Use it in a chat

    In a new chat, turn on the plugin and ask ChatGPT to use it.

Keep the link secret

The link contains a secret code for that one app. You chose this trade-off: anyone with the link can run that app’s tools in ChatGPT, read its website’s pages with your sign-in, save tools to it, and order if you turned ordering on, but nothing else. MCParrot keeps only a scrambled copy of the code, so it cannot show the link again, and it never writes the code to logs or Sentry. Keep the link private. If it leaks, select Regenerate link and replace the link in the ChatGPT connector. Your ChatGPT connectors from before this change use an older link with Vercel’s bypass secret, and they keep working for your own apps. While the Vercel sign-in is on, that secret opens the whole website, and Vercel blocks the new links, so new links start working once you turn the Vercel sign-in off. Other websites cannot use your signed-in browser to change MCParrot, and they cannot show MCParrot inside their own pages.

Using your assistant

  1. Ask for a result

    “Use Course portal to find my assignments due this week.”

    ChatGPT chooses a saved tool and supplies its inputs. Inputs it leaves out use the example value that Claude found.

  2. MCParrot runs the tool

    A hidden Browser Use browser opens the website with your saved sign-in and repeats the tool’s requests inside the website page, one after another. A request can go to any address on the website’s own domain, such as api-partner.spotify.com or spotify.com for open.spotify.com, but it must start the same way, such as with https; you chose this on October 18, 2026, because websites such as Spotify get their data from a sister address. Each request sends the labels that the extension recorded with it, but never cookies or sign-in codes from the recording; a hidden sign-in code is read fresh from the website’s page each time. A later request can use a value from an earlier answer. For example, a DoorDash tool “Add item to cart” first gets your cart, then sends that cart’s number in its second request, so ChatGPT never needs to know the number. If the earlier answer does not contain that value, ChatGPT gets an error that says which step and which value were missing. When an answer is a whole page, the browser opens that page, waits a few more seconds for pages that build their text after they open, and keeps only the text you would see. You never see this browser. It stays open for up to 10 minutes, so tool calls in the next 7 minutes use it again and answer about a second faster. Signing in, sending a code, preparing an order, and deleting the app close it first, so it does not save an older sign-in over the new one, except in a rare case that the status guide lists.

  3. Get the result

    ChatGPT receives the website’s answer, and nobody clicks through the website pages again. Before the answer goes to ChatGPT, MCParrot makes it shorter without AI, because long answers made ChatGPT slow. It removes empty values, fields that only track or measure your visits, and long codes that only the website can read, such as sign-in tokens and page markers, and it turns website formatting code, such as the markup inside an Ed post, into plain text. It keeps each picture’s address as “[image: address]”, so ChatGPT can still find the picture. A very long piece of text ends with a note that says how many characters were left out, and you chose a limit of 20,000 characters for each answer after this, with a note at the end when the answer was longer. When the limit falls inside a table, the answer stops after the last whole item, and the note says how many items it shows out of how many, that asking for the full answer will not show more, and that ChatGPT should ask you to narrow the request. In a test with a made-up Ed discussion, the answer became 31% shorter before that limit, and a made-up DoorDash store list became 64% shorter. A list of three or more similar items, such as Ed discussions or DoorDash stores, becomes a table: one line with the names of the parts, then one line for each item with its values separated by “ | ”. When a part has the same value in every item, such as the course of every Canvas assignment, the table names it once at the top, so a list of 25 made-up Canvas assignments became about a quarter shorter and fit whole in the answer. Removing the long codes then made that list and a made-up DoorDash home page about 45% and 35% shorter again. When a tool has answer fields, ChatGPT gets only those parts. If none of them is in the answer, ChatGPT gets the whole shortened answer. When the short answer lacks something it needs, ChatGPT can ask that tool for the full answer, which is still shortened but keeps every part. In a test on October 18, 2026, tables made a made-up list of 30 Ed discussions and a made-up DoorDash home page about 35% shorter again, and answer fields made them about 80% and 73% shorter than before tables. A later request still reads the full earlier answer, up to 100,000 characters. If the website takes longer than 30 seconds, returns an error, or sends the browser to another website, ChatGPT gets an error message instead. If the website shows a bot check to the hidden browser, ChatGPT says that the website blocked it. If the website refuses the request’s protection code, ChatGPT tells you to record that page again with MCParrot Explorer.

If the website has signed you out and the app signs in again automatically, MCParrot signs in again for you, as recovering an expired sign-in explains. Otherwise, ChatGPT shows a message that tells you to select Sign in to website in MCParrot or choose how the app signs in again, and then you ask again. Some websites need special codes that only their own page adds, so some saved tools can fail. Your assistant can combine tools to answer new requests, but one browsing session cannot prove support for every website feature.

You decided on October 17, 2026 that tools can send data to a website, not only read pages, because many websites, such as DoorDash, read and act through requests that send data. You accepted that such a tool can change things in your website account. MCParrot keeps one safety rule: it refuses any tool request whose address or sent data looks like checkout or payment, with words such as “checkout”, “payment”, “pay”, “purchase”, “place order”, “create order”, or “submit order”. For a request that only reads data, such as a DoorDash search, it checks only the request’s name, so a search that also asks for your saved payment method or past purchases still works. It checks this when Claude suggests a tool, when ChatGPT saves one, and every time a tool runs. A tool that sends data never follows the website to another address, so its data cannot reach another website. If the website was only sending it to the sign-in page, MCParrot treats the website as signed out; otherwise ChatGPT gets an error. This rule is there so that a tool can never pay with a card saved on a website; ordering happens only through Pay with Link. The page reader only opens pages, so this rule does not apply to it. Many websites also refuse sent data without a short anti-forgery code that changes often, so each time a tool that sends data runs, MCParrot reads a fresh code from the website’s home page or cookies in your signed-in browser and sends it with the request. It does the same for a tool that asks a GraphQL question, such as on Canvas, and for every LinkedIn tool, because those websites need the code even when a tool only reads. The code stays on the website’s page, and MCParrot never records it.

Equal controls for agents

Your agent is your assistant when it acts for you. Everything you can do in MCParrot must also be possible through your agent. For example, you can create a website app yourself, or you can ask your agent to create it with the same details. Both paths must give the same information and respect the same permissions. This rule covers actions and information, not the screen layout or moving between tabs.

The exploration controls follow this same rule: an agent must be able to start and stop exploration, list or delete recorded requests, find what a site can do, and save chosen tools. These matching agent controls remain aspirational.

The rule applies to app management, tool teaching, testing, sign-in, connections, progress, and recovery. We check both paths before we mark a feature shipped. Reading a picture follows the rule: the app page’s View image box and ChatGPT use the same steps. Ordering follows the rule: the app page’s Test order box and ChatGPT use the same steps, and ChatGPT can also see the Pay with Link status. Today, ChatGPT can run an app’s saved tools and read its pages, but it cannot manage MCParrot, change the ordering switch and limit, make a new link, publish an app, or browse and add marketplace apps, and the workspace has no button to run a tool or read a page, which is a gap listed on the status page.

You still control personal verification

Your agent could request exploration, but you still need the extension and your selected browser tab. You browse the website yourself. You still receive Duo’s text-message code on your phone and complete any other personal verification. You chose to type verification codes in the ChatGPT chat. Passwords never go into ChatGPT; you enter them only in MCParrot’s Save login form. MCParrot never asks for or types your Google password.

Recovering an expired sign-in

Websites sign you out after a while. The app page’s Website sign-in card has Sign in to website at the top, and below it a Sign in again automatically choice: Off, With Google, or With email and password. MCParrot saves your choice as soon as you select it. Apps from before this choice count as email and password if they have a saved login, and as off if they do not. When the choice is off, or there is no saved login, ChatGPT tells you to select Sign in to website in MCParrot or choose how the app signs in again. Signing in again with a saved login is shipped. The text-message code step and signing in again with Google are a gap until your live tests pass.

You decided on October 17, 2026, that websites such as DoorDash, where you select “Continue with Google”, sign in again with Google. When you sign in once with Sign in to website, the app’s browser remembers both the website and your Google account. With With Google, when a tool finds the website signed out, a Browser Use agent opens the website in that browser, selects “Continue with Google”, and picks your Google account. You can type your Google email in the optional Google account email box so the agent picks the right account when Google shows more than one; this email is not a secret. MCParrot never stores or types your Google password, and the agent never types anything on a Google page. If Google asks for a password, a code, or to verify that it’s you, ChatGPT says: “Open MCParrot and select Sign in to website on this app, then try again.” When the agent signs in, ChatGPT gets your answer in the same reply if there is time. After a failure, MCParrot waits 10 minutes before it tries again, unless you change the Google email.

With email and password, you only type the text-message code in ChatGPT. This works only on a normal sign-in form with username and password boxes, not with “Continue with Google”, and the card says so. To save a login, open the app page, select With email and password, enter your username and password in Save login, and select Save login. The page then only says Login saved, with Replace and Delete. MCParrot locks the details with a secret key before it stores them and never shows the password again, not to the page and not to ChatGPT. Saving also notes the website’s sign-in page, such as CalNet for Berkeley Canvas, and the password can only be typed on the website and that page. MCParrot takes the website address from the app you saved, not from the form. Deleting the app deletes its login, any sign-in that waits for a code, its last list of suggested tools, and any order in progress. Deleting a login does not sign you out of the website.

  1. A tool finds you signed out

    You ask ChatGPT for something, such as your course syllabus, and the website says you are signed out.

  2. Browser Use signs in

    A Browser Use agent opens the website in a hidden browser with your app’s saved sign-in. Browser Use types your username and password into the page itself, so the agent’s AI never sees them. It tries the password once. If the website rejects it, ChatGPT tells you to replace the login in MCParrot, and MCParrot never tries that login again until you replace it. Only one sign-in runs at a time for each app. After any other failure, MCParrot waits 10 minutes before it tries the same login again.

  3. The website asks for a code

    When Duo or a similar check appears, the agent chooses the text-message option, opening Other options if needed, and stops at the code box. The hidden browser waits for up to 15 minutes. ChatGPT tells you that a code was sent to your phone and asks you for it.

  4. You type the code in ChatGPT

    Type the code in the chat. ChatGPT passes it to MCParrot, and the agent enters it in the same browser and declines the offer to remember the device. If the website rejects the code, ChatGPT asks you for a new one. If you change the choice away from email and password while a code is waiting, MCParrot ignores that waiting sign-in.

  5. Ask again

    MCParrot closes the browser, which saves your new sign-in, and ChatGPT tells you sign-in finished. ChatGPT then runs your tool again. If the website did not ask for a code, the tool continues straight away when enough time is left in the same request; otherwise ChatGPT runs it again.

MCParrot does not keep the code after it uses it, and Sentry never receives codes or passwords. Your agent will be able to check whether a login is saved or delete it, but it will never read your password; these agent controls are aspirational.

Needs a real school test

The sign-in rules of a school, device checks, or Duo settings may stop automatic sign-in. In that case ChatGPT shows a clear message that tells you to select Sign in to website in MCParrot. No visible browser opens during ChatGPT use. We have not yet tested automatic sign-in on Berkeley Canvas.

Ordering with Pay with Link

You decided that ChatGPT and the app page can order food or goods for you. A Browser Use agent fills the cart on the website and pays with Browser Use’s Pay with Link, which uses Stripe Link. Link makes a one-time card for each payment you approve, so MCParrot never stores your card number or its security code. DoorDash is the first website you want to use. Your firm rule is that ordering must never charge your real card, so MCParrot only places an order while Link is in test mode. This feature is a gap until a live test passes.

You decided that only you can order, because orders use your Browser Use account and its Link connection. Other people do not see the Ordering section, and MCParrot refuses their orders from the app page and from ChatGPT. Each of your app pages has an Ordering section. It has an Allow ordering from ChatGPT and from this page switch, which starts off, and a spending limit for each order in US dollars, up to $500, because Link refuses larger payments. The section also shows whether Pay with Link is connected and whether it is in test mode or live mode. Live mode shows that it is blocked. ChatGPT only sees the ordering tools while the switch is on.

  1. Ask for an order

    Ask ChatGPT to order something, or type it in the Test order box on the app page and select Prepare order.

  2. Browser Use fills the cart

    A hidden Browser Use agent opens the website with your app’s saved sign-in, adds the items, and opens the checkout page. It never presses a button that places the order or pays. This takes a few minutes, so ChatGPT checks back, and the app page refreshes by itself.

  3. Check the cart

    ChatGPT shows every item, the fees, the tip, the total, the delivery address, and when it should arrive, and asks you to approve the exact total. The app page shows the same cart with Place order and Cancel order.

  4. MCParrot checks the rules

    When you approve, MCParrot checks that Link is in test mode and that the total is within your limit. A short agent step then reads the checkout total again without paying. If the total changed, MCParrot stops and shows you the new total to approve.

  5. Approve in the Link app

    Only now does the agent get permission to pay with Link. Link sends a notice to your phone, and you approve the payment in the Link app.

  6. Get the result

    ChatGPT, or the app page, shows the website’s confirmation or why the payment failed. MCParrot then closes the browser.

Selecting Cancel order, or asking ChatGPT to cancel, stops the agent and closes its browser, but the items can stay in the website’s cart. Only one order runs at a time for each app, and MCParrot keeps its progress for one hour after its last change. The browser stays open for 30 minutes after each step so you have time to approve, but Browser Use closes it after 2 minutes on free accounts. Each order may use at most $5 of Browser Use credit. The app must be signed in with Sign in to website first; orders do not sign in again by themselves. If a payment fails for an unclear reason, check the website’s order history before you try again, because the order may have gone through.

Test mode only

MCParrot checks Link’s mode on its server, not only in the agent’s instructions. In live mode, or when it cannot read the mode, it refuses to place the order, and no setting changes this for now. Test mode means a payment can only succeed on a website that accepts Stripe test cards. DoorDash has no test mode, so on DoorDash the payment step cannot succeed: DoorDash declines the test Link card, and the order stops with that message. A card saved in your website account is a risk the code cannot fully block, because only the agent’s instructions tell it not to use that card. Remove every saved card from your website account before you test.

Questions that need proof

  • Saved tools appear in ChatGPT without a test, so we must check that each one works for you.
  • Pages you never visited remain unsupported unless discovered and tested separately.
  • Pages that fill in their content only after you click something can come back with part of their text missing.
  • Some website messages may work only inside the original browser.
  • A changed website may need another recording.
  • We must measure speed before we say the product is faster.
  • When a tool needs a hidden sign-in code, such as Ed’s, it reads the code from the signed-in cloud browser each time it runs and sends it only to the website. The code never reaches our server, ChatGPT, or Sentry. This works only when the website keeps the code in the browser’s storage, as plain text or inside a stored group of values, and Ed tools need a new recording with MCParrot Explorer 0.6.0 or later. The tool details on the app page show which labels a tool sends and where it reads them, never the codes.
  • A tool that sends data can change things in your website account, and no such tool has run on a real website yet.
  • MCParrot spots checkout and payment steps by their words, so a payment step with an unusual name can still pass, and a harmless step that mentions payment is refused.

Make failures useful

Sentry is a service that reports errors and slow steps in an app. MCParrot sends it error reports, the timing of each step (Tracing), short log lines (Logs), screen recordings of the workspace with all text, inputs, and link and picture addresses hidden (Session Replay), and the timing of each Claude discovery call and ChatGPT tool call (AI agent monitoring). Logs go through Sentry itself, not through Vercel’s log forwarding feature. Sentry never receives passwords, verification codes, cookies, website answers, the values ChatGPT sends to tools, delivery addresses, the items you order, or the private link secret. For orders, it only receives whether each step worked and the amounts. ChatGPT first asks for the newest connection version, 2026-07-28, which no MCP toolkit supports yet; MCParrot answers with the versions it supports, ChatGPT then uses the older version, and Sentry ignores that expected first error. Sentry also ignores expected tool results, such as a signed-out website or a rejected login. The demonstration should show a real problem that these tools helped us fix.
