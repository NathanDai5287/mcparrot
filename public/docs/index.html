What exists today

You can open the hosted workspace today and create website apps, explore them, let Cursor Composer find what each site can do, and save the tasks you choose, which is shipped. Your live test of exploring a website is still a gap. Testing tasks and using them from your assistant are aspirational, so the rest of this guide describes the finished experience. The status page lists every feature with its status, the known gaps, and the order of the remaining work.

Where the app runs

The website has a Vercel project on the existing free Hobby plan. It is connected to our public GitHub repository. Updates to the main version publish to the production website, and other branches receive preview links. The status page records which of the parts below run today.

How the product works

You create an app for one website, browse its pages, and review several suggested tasks from that session. Your assistant, such as ChatGPT, then uses all the tasks of a website app through one MCP connection. MCP is a standard way for an assistant to find and use the tools that you saved in another app, and each task you test and enable becomes one of those tools. The product is intended for many websites, not one fixed example.

During teaching, also called parroting, MCParrot Explorer records the data requests a website makes in a normal Chrome or Edge tab. During later assistant use, no visible website browser opens. The app uses saved website requests where supported and a hidden browser for steps that need one. You enter any supported sign-in recovery details or verification codes inside our app. Exploration does not use a cloud browser.

Teaching a website task

Teaching has three steps: explore, discover, and choose. Exploring and choosing are shipped, but your live test of the extension is still a gap. Testing tasks and turning them into assistant tools are aspirational. These steps work for any website, not only course sites.

  1. Create your app

    Visit our website, select Create app, and enter the website address. For example, name the app after the site you use.

  2. Install the extension once

    Select Explore website. Download MCParrot Explorer and extract its ZIP. Open your browser’s Extensions page, enable Developer mode, select Load unpacked, and choose the extracted folder. Reload MCParrot. It works in Chrome and Edge and is not in an extension store. To update it, remove the old copy first, then load the new folder.

  3. Explore the website

    Select Open website and explore. A normal tab opens at the app’s website address. Sign in as usual and complete Duo or any other check. Browse the pages and features you want your assistant to use. Return to MCParrot and select Stop exploring.

  4. Find what the site can do

    Select Find what this site can do. Cursor Composer reads the recorded requests and returns a list of things your assistant could do, such as listing assignments. Each item shows what it does, which values you can change, and what it returns.

  5. Choose your tasks

    Tick the items you want, change their names or descriptions if you like, and select Save tasks. Saving replaces the app’s current tasks, and the app page lists them. Your tasks stay in this browser.

  6. Explore more when needed

    Select Continue exploring to add pages without losing earlier requests. Then find what the site can do again and choose again.

You are the teacher

You browse pages once, then choose which suggested tasks to keep. Composer’s list is a set of guesses from one visit, so a task is not a usable tool until a test with changed values passes. The first milestone only reads information. The app must not try actions that change website data automatically.

What the extension records

The extension records only in the tab it opens for you. While it records, your browser shows a bar that says MCParrot Explorer is debugging the browser. It keeps each data request the page makes: its type, its full address, whether it worked, the kind of answer, and a short sample of that answer. Long text is cut to 80 characters, lists keep only 2 items, and each sample stays small.

It skips pictures, fonts, styles, scripts, and media. It skips common tracking services and sign-in pages. It never copies passwords, cookies, message headers, or what your browser sends to the website. Similar requests are kept once, up to 150 for each app.

Recording stops when you select Stop exploring, close the tab, close the debugging bar, or restart the browser. Recorded requests stay in the extension until you select Delete recorded requests, delete the app, or remove the extension. Apps keep stable addresses, so Back and Forward work. The extension works with the production website and with the local test website on your computer.

What Composer sees

When you select Find what this site can do, our website sends the recorded requests and their short samples to Cursor Composer 2.5 Fast through the Cursor SDK. Composer works in an empty folder, so it cannot read our project files, and it only replies with the list of tasks. You chose real short samples because they help Composer make better suggestions. Sending website content to the AI is fine; only secrets stay out. Nothing goes to Composer until you select that button, and no passwords, cookies, headers, or sign-in traffic are included.

Only you can use this feature, because Vercel asks you to sign in before you can open the website. If Composer is not set up, does not start, or does not finish, the page shows a clear error message.

Using your assistant

This experience after you teach a task is aspirational.

  1. Connect once

    Add the MCP address of your app to a compatible assistant, such as ChatGPT where it is supported.

  2. Ask for a result

    “Find my assignments due this week.”

    Your assistant chooses an enabled tool and supplies its inputs.

  3. Get the result

    The app repeats the saved website messages with your active login. Your assistant receives the result, and nobody needs to click through the website pages again.

Your assistant can combine enabled tools to answer new requests. One browsing session can expose several reading requests, but it cannot prove support for every website feature. An unsupported action needs more discovery and testing. Some actions may still need a hidden browser, and we must test those steps before we enable their tools. Assistant use must never open a visible website browser window.

Two kinds of connections

Each website app will get its own connection, and MCParrot will get a separate management connection. Both kinds are aspirational.

For example, two website apps give you two website connections, and the management connection makes three in total. Each website connection includes all the enabled tasks of that app, so you do not connect each task separately. You need the management connection only if you want your assistant to manage MCParrot for you. All connections come from our one hosted website.

  1. Choose a connection

    Open the connection details of the website app, or choose MCParrot management.

  2. Add it to your assistant

    Copy its address and follow the setup instructions for your compatible assistant.

  3. Authorize access

    Sign in and approve access to your own apps and tasks. The available connection options depend on your assistant.

Equal controls for agents

Your agent is your assistant when it acts for you. Everything you can do in MCParrot must also be possible through your agent. For example, you can create a website app yourself, or you can ask your agent to create it with the same details. Both paths must give the same information and respect the same permissions. This rule covers actions and information, not the screen layout or moving between tabs.

The exploration controls follow this same rule: an agent must be able to start and stop exploration, list or delete recorded requests, find what a site can do, and save chosen tasks. These matching agent controls remain aspirational.

The rule applies to app management, task teaching, testing, connections, progress, and recovery as those features become available. We check both paths before we mark a feature shipped. Today, the workspace has no agent connection, which is a gap listed on the status page.

You still control personal verification

Your agent could request exploration, but you still need the extension and your selected browser tab. You browse the website yourself. You still approve Duo on your phone and complete any other personal verification. After that, your agent checks progress and continues the supported work. Keep passwords and verification codes out of assistant messages.

Recovering an expired sign-in

A saved login can expire, and your task then needs a new sign-in. This recovery experience is aspirational.

You can choose to save a username and password separately for each website app. Enter them only in a private MCParrot form. You can replace or delete them later. The app uses them only for that website and its approved sign-in page. It does not collect passwords while you explore or copy them from your browser.

Your normal browser and the hidden browser have separate sign-ins. After the assistant connection exists, Browser Use will sign in and pass these checks when your tasks run. Saved details let it try again later; you still enter each text code yourself. Your assistant can request a private entry page or check whether details are saved, but it cannot read your password.

  1. The browser attempts sign-in

    If you chose to save your sign-in details securely, Browser Use enters them and continues as far as possible. If not, you enter your sign-in details through a secure page inside our app.

  2. Your assistant shows a verification request

    The tool gives a Verification required status and a link that your assistant can show you.

  3. You complete verification

    Enter a verification code on the secure page, or approve Duo on your phone. Keep passwords and verification codes out of assistant messages.

  4. The task continues

    The browser finishes sign-in, and the app tries to continue the waiting task. Some assistants may need to check the task status before they show the result.

User-managed saved logins remain aspirational. They need private account access and encrypted storage before you can use them. Verification codes are not saved. Deleting saved details will remove them from MCParrot; it will not sign out existing website sessions.

Needs a real school test

The sign-in rules of a school may prevent parts of this flow. Unsupported recovery must show a clear failure instead of opening a visible website browser. We have not tested automatic sign-in or Duo recovery on the website of your school.

Questions that need proof

  • Suggested tasks must pass a test with different inputs before your assistant can use them.
  • Pages you never visited remain unsupported unless discovered and tested separately.
  • Some pages return a whole document instead of separate data messages, so their tasks need another tested method.
  • Some website messages may work only inside the original browser.
  • A changed website may need another recording.
  • We must measure speed before we say the product is faster.
  • The first milestone only reads information. Actions that change website data need a separate plan.

Our first build milestone

First, you browse a reading page, review one suggested task, and test it with different inputs against the website. The order of remaining work lists every later stage and how we know each one is finished.

Make failures useful

Sentry is a service that reports errors and slow steps in an app. We intend to use its error reports, Tracing, and Logs to find failed or slow tasks. The demonstration should show a real problem that these tools helped us fix.
