What exists today

You can open the hosted workspace today and create website apps, explore them, let Cursor Composer find what each site can do, and save the tasks you choose, which is shipped. Each app page also lets you sign in to the website once and copy a private link for ChatGPT. Those two steps and asking ChatGPT to run a task are a gap until your live test passes. Testing tasks before they become tools and the management connection are aspirational. The status page lists every feature with its status, the known gaps, and the order of the remaining work.

Where the app runs

The website has a Vercel project on the existing free Hobby plan. It is connected to our public GitHub repository. Updates to the main version publish to the production website, and other branches receive preview links. The status page records which of the parts below run today.

How the product works

You create an app for one website, browse its pages, and review several suggested tasks from that session. Your assistant, such as ChatGPT, then uses all the tasks of a website app through one MCP connection. MCP is a standard way for an assistant to find and use the tools that you saved in another app, and each saved reading task becomes one of those tools. The product is intended for many websites, not one fixed example.

During teaching, also called parroting, MCParrot Explorer records the pages you open and the data requests they make in a normal Chrome or Edge tab. Exploration does not use a cloud browser. You then sign in once in a Browser Use cloud browser that you see in a popup. During later assistant use, no visible website browser opens: each task runs in a hidden Browser Use browser that keeps your sign-in.

Teaching a website task

Teaching has three steps: explore, discover, and choose. Exploring and choosing are shipped, but your live test of the extension is still a gap. Testing tasks before they become tools is aspirational. These steps work for any website, not only course sites.

  1. Create your app

    Visit our website, select Create app, and enter the website address. For example, name the app after the site you use.

  2. Install the extension once

    Select Explore website. Download MCParrot Explorer and extract its ZIP. Open your browser’s Extensions page, enable Developer mode, select Load unpacked, and choose the extracted folder. Reload MCParrot. It works in Chrome and Edge and is not in an extension store. To update it, remove the old copy first, then load the new folder.

  3. Explore the website

    Select Open website and explore. A normal tab opens at the app’s website address. Sign in as usual and complete Duo or any other check. Browse the pages and features you want your assistant to use. Return to MCParrot and select Stop exploring.

  4. Find what the site can do

    Select Find what this site can do. Cursor Composer reads the recorded requests and the tasks you already saved, and returns a list of things your assistant could do, such as listing assignments. It leaves out what your saved tasks already do. Each item shows what it does, which values you can change, and what it returns. Each item is marked “New”, or “Updates” and a task’s name when it is a clearly better version of a task you saved. MCParrot keeps the last list with its time, so when you come back to this page you see it again without a new paid run. Select Find what this site can do again when you want a new list.

  5. Choose your tasks

    Tick the items you want, change their names or descriptions if you like, and select Save tasks. Saving adds the new ones to the app’s current tasks and skips any you already have with the same name or page, so tasks ChatGPT saved stay. Saving an update replaces the task it names and keeps it in the same place. Items you saved disappear from the last list. If you rename an update before you save it, it shows again until the next new list. The app page lists them, each with a Delete button. Each saved reading task becomes a tool in the app’s ChatGPT connection right away.

  6. Explore more when needed

    Select Continue exploring to add pages without losing earlier requests. Then find what the site can do again and choose again.

You are the teacher

You browse pages once, then choose which suggested tasks to keep. Composer’s list is a set of guesses from one visit, so a saved task can fail when ChatGPT runs it. A test with changed values before a task becomes a tool is aspirational. The first milestone only reads information. The app must not try actions that change website data automatically.

What the extension records

The extension records only in the tab it opens for you. While it records, your browser shows a bar that says MCParrot Explorer is debugging the browser. It keeps each data request the page makes: its type, its full address, whether it worked, the kind of answer, and a short sample of that answer. Long text is cut to 80 characters, lists keep only 2 items, and each sample stays small.

You chose to also record each whole page you open, such as a course syllabus, because some pages arrive in one piece and never make a separate data request. For a page, the extension keeps its address, whether it worked, and the first 3,000 characters of the text you see on it, not the page’s code. Composer can then suggest tasks that read a page, such as “Read course syllabus” for any course.

It skips pictures, fonts, styles, scripts, and media. It skips common tracking services and pages whose address has a sign-in word, such as “login”, “session”, or “token”. It never copies passwords, cookies, message headers, or what your browser sends to the website. It writes “redacted” in place of values that look secret: address values named like “token” or “code”, long random codes, and answer values named like “password” or “session”. It finds secrets only by these patterns, so a secret in another form can still be kept. Similar requests and pages are kept once, up to 150 for each app.

Recording stops when you select Stop exploring, close the tab, close the debugging bar, or restart the browser. Recorded requests stay in the extension until you select Delete recorded requests, delete the app, or remove the extension. The extension also deletes a recording 30 days after its last request. The extension only asks your browser for permission to store data and to watch the tab it opens, not to read every website. Apps keep stable addresses, so Back and Forward work. The extension works with the production website and with the local test website on your computer.

What Composer sees

When you select Find what this site can do, our website sends the recorded requests and pages and their short samples to Cursor Composer 2.5 Fast through the Cursor SDK, together with the app’s saved tasks, which our website reads from its own storage. Composer has its tools turned off and works in an empty folder that is deleted afterwards, so it cannot read our project files, and it only replies with the list of tasks. Our website hides secret-looking values a second time before it sends anything, and it tells Composer never to follow instructions inside the recording. It keeps only suggested tasks that read information from the same website. You chose real short samples because they help Composer make better suggestions. Sending website content to the AI is fine; only secrets stay out. Nothing goes to Composer until you select that button, and no passwords, cookies, headers, or sign-in pages are included, although a secret in a form that our patterns miss can still reach Composer.

Only you, or someone with an app’s private ChatGPT link, can use this feature, because Vercel asks everyone else to sign in before they can open the website. If Composer is not set up, does not start, does not finish within 50 seconds, or the recording is too large, the page shows a clear error message.

Signing in once

Your assistant needs your website sign-in to read your information. You chose to sign in once in a Browser Use cloud browser that remembers the sign-in for that app. This step is a gap until your live test passes. Your normal browser and this cloud browser have separate sign-ins, so signing in while you explore does not count.

  1. Start sign-in

    Open the app page and select Sign in to website. A popup opens with a cloud browser at the website. If your browser blocks the popup, select Open the sign-in window.

  2. Sign in

    Sign in as usual in the popup and complete Duo or any other check. You have 15 minutes.

  3. Finish

    Return to MCParrot and select Done signing in. The cloud browser closes and saves your sign-in. The app page and app list then show that the app is signed in.

You can also save your login on the app page, so MCParrot signs in again by itself when the website signs you out. Recovering an expired sign-in explains how.

Connecting ChatGPT

Each website app gets its own private connection link, which gives ChatGPT that app’s reading tasks. This link is a gap until your live ChatGPT test passes. You chose to build only these app connections first. A separate MCParrot connection that would let ChatGPT manage your apps is aspirational.

Only reading tasks appear in ChatGPT, and each one becomes a tool named after the task. Give every task in an app a clearly different name. Changing only capitals, spaces, or punctuation does not count, so “Read Course” and “Read-Course” get the same tool name. Do not name a task after a built-in tool, such as “Read page”, “Save task”, or “Submit verification code”. Each tool in a connection needs its own name, so MCParrot does not save a task with such a name. If two older tasks still share a name, ChatGPT sees the second one with a short code added to its name.

Each connection also has a tool called “Read a page on” your app’s name. ChatGPT gives it a page address on that website, such as a syllabus link you paste, and MCParrot opens the page with your saved sign-in in a hidden browser and returns its text. It refuses addresses on any other website. It uses the same length limit and the same sign-in recovery as tasks. You chose this trade-off: ChatGPT can read any page your account can see on that website, not only the tasks you chose. It only opens pages, so it changes nothing unless just opening a page changes something on that website, such as a sign-out link.

Each connection also has a tool called “Save a page as a task for” your app’s name, so your connection grows while you use it. When ChatGPT finds something useful with the page reader, such as your syllabus, it saves that page as a task and swaps values that change, such as the course number, for blanks it can fill next time. It refuses pages on other websites, blanks without a matching value, and tasks whose name or page address you already have. The task appears on the app page and becomes its own tool when you start a new ChatGPT chat. You chose to let ChatGPT save tasks without asking you first, so delete any task you do not want on the app page. Every change you make on the app page only touches that one app or task, so a page you opened earlier never removes a task ChatGPT saved.

  1. Copy the link

    On the app page, select Copy link.

  2. Open the plugin directory

    In ChatGPT, open Settings, then Plugins, and select Browse directory.

  3. Add the server

    Select Add, then Add custom MCP server. Name it after your app, paste the link as the Server URL, set Authentication to No authentication, tick the risk notice, and select Create as a plugin.

  4. Use it in a chat

    In a new chat, turn on the plugin and ask ChatGPT to use it.

Keep the link secret

The link contains a secret code that lets ChatGPT past Vercel’s sign-in. You chose this trade-off: anyone with the link can use the whole MCParrot website, not only that app. With it, a person can see all your apps and their links, add or delete apps and tasks, save or delete logins, ask Composer for tasks, and open a live browser with an app’s sign-in. Whether to limit the link to ChatGPT’s connection is still your decision. Other websites cannot use your signed-in browser to change MCParrot, and they cannot show MCParrot inside their own pages. Keep the link private. If it leaks, open the Vercel project, go to Settings, then Deployment Protection, then Protection Bypass for Automation, and make a new secret. Then publish again, copy each app’s new link, and replace the link in each ChatGPT connector.

Using your assistant

  1. Ask for a result

    “Use Course portal to find my assignments due this week.”

    ChatGPT chooses a saved task and supplies its inputs. Inputs it leaves out use the example value that Composer found.

  2. MCParrot runs the task

    A hidden Browser Use browser opens the website with your saved sign-in and repeats the task’s requests inside the website page. When an answer is a whole page, the browser opens that page and keeps only the text you would see. You never see this browser.

  3. Get the result

    ChatGPT receives the website’s answer, and nobody clicks through the website pages again. You chose a limit of 100,000 characters for each answer, so long lists, such as all your courses, arrive whole. If the website takes longer than 30 seconds, returns an error, or sends the browser to another website, ChatGPT gets an error message instead.

If the website has signed you out and you saved a login, MCParrot signs in again for you, as recovering an expired sign-in explains. Without a saved login, ChatGPT shows a message that tells you to save a login or select Sign in to website in MCParrot, and then you ask again. Tasks only read information in this first version, so tasks that would change website data do not appear in ChatGPT. Some websites need special codes that only their own page adds, so some saved tasks can fail. Your assistant can combine tasks to answer new requests, but one browsing session cannot prove support for every website feature.

Equal controls for agents

Your agent is your assistant when it acts for you. Everything you can do in MCParrot must also be possible through your agent. For example, you can create a website app yourself, or you can ask your agent to create it with the same details. Both paths must give the same information and respect the same permissions. This rule covers actions and information, not the screen layout or moving between tabs.

The exploration controls follow this same rule: an agent must be able to start and stop exploration, list or delete recorded requests, find what a site can do, and save chosen tasks. These matching agent controls remain aspirational.

The rule applies to app management, task teaching, testing, sign-in, connections, progress, and recovery. We check both paths before we mark a feature shipped. Today, ChatGPT can run an app’s saved tasks and read its pages, but it cannot manage MCParrot, and the workspace has no button to run a task or read a page, which is a gap listed on the status page.

You still control personal verification

Your agent could request exploration, but you still need the extension and your selected browser tab. You browse the website yourself. You still receive Duo’s text-message code on your phone and complete any other personal verification. You chose to type verification codes in the ChatGPT chat. Passwords never go into ChatGPT; you enter them only in MCParrot’s Save login form.

Recovering an expired sign-in

Websites sign you out after a while. If you saved a login for the app, MCParrot signs in again by itself while ChatGPT runs your task, and you only type the text-message code in ChatGPT. This is a gap until your live Canvas test passes. Without a saved login, ChatGPT tells you to save one or select Sign in to website in MCParrot.

To save a login, open the app page, enter your username and password in Save login, and select Save login. The page then only says Login saved, with Replace and Delete. MCParrot locks the details with a secret key before it stores them and never shows the password again, not to the page and not to ChatGPT. Saving also notes the website’s sign-in page, such as CalNet for Berkeley Canvas, and the password can only be typed on the website and that page. MCParrot takes the website address from the app you saved, not from the form. Deleting the app deletes its login, any sign-in that waits for a code, and its last list of suggested tasks. Deleting a login does not sign you out of the website.

  1. A task finds you signed out

    You ask ChatGPT for something, such as your course syllabus, and the website says you are signed out.

  2. Browser Use signs in

    A Browser Use agent opens the website in a hidden browser with your app’s saved sign-in. Browser Use types your username and password into the page itself, so the agent’s AI never sees them. It tries the password once. If the website rejects it, ChatGPT tells you to replace the login in MCParrot, and MCParrot never tries that login again until you replace it. Only one sign-in runs at a time for each app. After any other failure, MCParrot waits 10 minutes before it tries the same login again.

  3. The website asks for a code

    When Duo or a similar check appears, the agent chooses the text-message option, opening Other options if needed, and stops at the code box. The hidden browser waits for up to 15 minutes. ChatGPT tells you that a code was sent to your phone and asks you for it.

  4. You type the code in ChatGPT

    Type the code in the chat. ChatGPT passes it to MCParrot, and the agent enters it in the same browser and declines the offer to remember the device. If the website rejects the code, ChatGPT asks you for a new one.

  5. Ask again

    MCParrot closes the browser, which saves your new sign-in, and ChatGPT tells you sign-in finished. ChatGPT then runs your task again. If the website did not ask for a code, the task continues straight away when enough time is left in the same request; otherwise ChatGPT runs it again.

MCParrot does not keep the code after it uses it, and Sentry never receives codes or passwords. Your agent will be able to check whether a login is saved or delete it, but it will never read your password; these agent controls are aspirational.

Needs a real school test

The sign-in rules of a school, device checks, or Duo settings may stop automatic sign-in. In that case ChatGPT shows a clear message that tells you to select Sign in to website in MCParrot. No visible browser opens during ChatGPT use. We have not yet tested automatic sign-in on Berkeley Canvas.

Moving around the workspace

Each app and its exploration page have their own web address, so your browser’s Back and Forward buttons return to the screen you saw, and refreshing the page keeps your apps and tasks. The same apps appear on any device where you open MCParrot. To remove an app, open it, select Delete app, and confirm on the same page. This removes the app and its tasks from MCParrot and deletes its recorded requests in the extension, but your account on the website stays. An old link to a deleted app shows a page that says the app is unavailable, with a way back to your app list.

Questions that need proof

  • Saved tasks become tools without a test, so we must check that each one works for you.
  • Pages you never visited remain unsupported unless discovered and tested separately.
  • Pages that fill in their content only after you click something can come back with part of their text missing.
  • Some website messages may work only inside the original browser.
  • A changed website may need another recording.
  • We must measure speed before we say the product is faster.
  • The first milestone only reads information. Actions that change website data need a separate plan.

Our first build milestone

First, you browse a reading page, save one suggested task, sign in once, and ask ChatGPT to run it with different inputs. The order of remaining work lists every later stage and how we know each one is finished.

Make failures useful

Sentry is a service that reports errors and slow steps in an app. MCParrot sends it error reports, the timing of each step (Tracing), short log lines (Logs), screen recordings of the workspace with all text, inputs, and link and picture addresses hidden (Session Replay), and the timing of each Cursor Composer and ChatGPT tool call (AI agent monitoring). Logs go through Sentry itself, because the Vercel log forwarding feature needs a paid plan. Sentry never receives passwords, verification codes, cookies, website answers, the values ChatGPT sends to tools, or the private link secret. ChatGPT first asks for the newest connection version, 2026-07-28, which no MCP toolkit supports yet; MCParrot answers with the versions it supports, ChatGPT then uses the older version, and Sentry ignores that expected first error. Sentry also ignores expected task results, such as a signed-out website or a rejected login. The demonstration should show a real problem that these tools helped us fix.
