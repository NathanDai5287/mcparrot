What exists today

You can open the hosted workspace today and create website apps, explore them, let Cursor Composer find what each site can do, and save the tasks you choose, which is shipped. Each app page also lets you sign in to the website once and copy a private link for ChatGPT. Those two steps and asking ChatGPT to run a task are a gap until your live test passes. Testing tasks before they become tools and the management connection are aspirational. The status page lists every feature with its status, the known gaps, and the order of the remaining work.

Where the app runs

The website has a Vercel project on the existing free Hobby plan. It is connected to our public GitHub repository. Updates to the main version publish to the production website, and other branches receive preview links. The status page records which of the parts below run today.

How the product works

You create an app for one website, browse its pages, and review several suggested tasks from that session. Your assistant, such as ChatGPT, then uses all the tasks of a website app through one MCP connection. MCP is a standard way for an assistant to find and use the tools that you saved in another app, and each saved reading task becomes one of those tools. The product is intended for many websites, not one fixed example.

During teaching, also called parroting, MCParrot Explorer records the data requests a website makes in a normal Chrome or Edge tab. Exploration does not use a cloud browser. You then sign in once in a Browser Use cloud browser that you see in a popup. During later assistant use, no visible website browser opens: each task runs in a hidden Browser Use browser that keeps your sign-in.

Teaching a website task

Teaching has three steps: explore, discover, and choose. Exploring and choosing are shipped, but your live test of the extension is still a gap. Testing tasks before they become tools is aspirational. These steps work for any website, not only course sites.

  1. Create your app

    Visit our website, select Create app, and enter the website address. For example, name the app after the site you use.

  2. Install the extension once

    Select Explore website. Download MCParrot Explorer and extract its ZIP. Open your browser’s Extensions page, enable Developer mode, select Load unpacked, and choose the extracted folder. Reload MCParrot. It works in Chrome and Edge and is not in an extension store. To update it, remove the old copy first, then load the new folder.

  3. Explore the website

    Select Open website and explore. A normal tab opens at the app’s website address. Sign in as usual and complete Duo or any other check. Browse the pages and features you want your assistant to use. Return to MCParrot and select Stop exploring.

  4. Find what the site can do

    Select Find what this site can do. Cursor Composer reads the recorded requests and returns a list of things your assistant could do, such as listing assignments. Each item shows what it does, which values you can change, and what it returns.

  5. Choose your tasks

    Tick the items you want, change their names or descriptions if you like, and select Save tasks. Saving replaces the app’s current tasks, and the app page lists them. Each saved reading task becomes a tool in the app’s ChatGPT connection right away.

  6. Explore more when needed

    Select Continue exploring to add pages without losing earlier requests. Then find what the site can do again and choose again.

You are the teacher

You browse pages once, then choose which suggested tasks to keep. Composer’s list is a set of guesses from one visit, so a saved task can fail when ChatGPT runs it. A test with changed values before a task becomes a tool is aspirational. The first milestone only reads information. The app must not try actions that change website data automatically.

What the extension records

The extension records only in the tab it opens for you. While it records, your browser shows a bar that says MCParrot Explorer is debugging the browser. It keeps each data request the page makes: its type, its full address, whether it worked, the kind of answer, and a short sample of that answer. Long text is cut to 80 characters, lists keep only 2 items, and each sample stays small.

It skips pictures, fonts, styles, scripts, and media. It skips common tracking services and sign-in pages. It never copies passwords, cookies, message headers, or what your browser sends to the website. Similar requests are kept once, up to 150 for each app.

Recording stops when you select Stop exploring, close the tab, close the debugging bar, or restart the browser. Recorded requests stay in the extension until you select Delete recorded requests, delete the app, or remove the extension. Apps keep stable addresses, so Back and Forward work. The extension works with the production website and with the local test website on your computer.

What Composer sees

When you select Find what this site can do, our website sends the recorded requests and their short samples to Cursor Composer 2.5 Fast through the Cursor SDK. Composer works in an empty folder, so it cannot read our project files, and it only replies with the list of tasks. You chose real short samples because they help Composer make better suggestions. Sending website content to the AI is fine; only secrets stay out. Nothing goes to Composer until you select that button, and no passwords, cookies, headers, or sign-in traffic are included.

Only you can use this feature, because Vercel asks you to sign in before you can open the website. If Composer is not set up, does not start, or does not finish, the page shows a clear error message.

Signing in once

Your assistant needs your website sign-in to read your information. You chose to sign in once in a Browser Use cloud browser that remembers the sign-in for that app. This step is a gap until your live test passes. Your normal browser and this cloud browser have separate sign-ins, so signing in while you explore does not count.

  1. Start sign-in

    Open the app page and select Sign in to website. A popup opens with a cloud browser at the website. If your browser blocks the popup, select Open the sign-in window.

  2. Sign in

    Sign in as usual in the popup and complete Duo or any other check. You have 15 minutes.

  3. Finish

    Return to MCParrot and select Done signing in. The cloud browser closes and saves your sign-in. The app page and app list then show that the app is signed in.

Connecting ChatGPT

Each website app gets its own private connection link, which gives ChatGPT that app’s reading tasks. This link is a gap until your live ChatGPT test passes. You chose to build only these app connections first. A separate MCParrot connection that would let ChatGPT manage your apps is aspirational.

  1. Copy the link

    On the app page, select Copy link.

  2. Turn on Developer mode

    In ChatGPT, open Settings, then Apps & Connectors, then Advanced settings, and turn on Developer mode.

  3. Create the connector

    Select Create, name it after your app, paste the link as the MCP server URL, and choose No authentication.

Keep the link secret

The link contains a secret code that lets ChatGPT past Vercel’s sign-in. You chose this trade-off: anyone with the link can use the whole MCParrot website, not only that app. Keep it private. If it leaks, open the Vercel project, go to Settings, then Deployment Protection, then Protection Bypass for Automation, and make a new secret. Then publish again, copy each app’s new link, and replace the link in each ChatGPT connector.

Using your assistant

  1. Ask for a result

    “Use Course portal to find my assignments due this week.”

    ChatGPT chooses a saved task and supplies its inputs. Inputs it leaves out use the example value that Composer found.

  2. MCParrot runs the task

    A hidden Browser Use browser opens the website with your saved sign-in and repeats the task’s requests inside the website page. You never see this browser.

  3. Get the result

    ChatGPT receives the website’s answer, shortened if it is very long, and nobody clicks through the website pages again.

If the website has signed you out, ChatGPT shows a message that tells you to select Sign in to website in MCParrot. Sign in again, then ask again. Tasks only read information in this first version, so tasks that would change website data do not appear in ChatGPT. Some websites need special codes that only their own page adds, so some saved tasks can fail. Your assistant can combine tasks to answer new requests, but one browsing session cannot prove support for every website feature.

Equal controls for agents

Your agent is your assistant when it acts for you. Everything you can do in MCParrot must also be possible through your agent. For example, you can create a website app yourself, or you can ask your agent to create it with the same details. Both paths must give the same information and respect the same permissions. This rule covers actions and information, not the screen layout or moving between tabs.

The exploration controls follow this same rule: an agent must be able to start and stop exploration, list or delete recorded requests, find what a site can do, and save chosen tasks. These matching agent controls remain aspirational.

The rule applies to app management, task teaching, testing, sign-in, connections, progress, and recovery. We check both paths before we mark a feature shipped. Today, ChatGPT can run an app’s saved tasks, but it cannot manage MCParrot, which is a gap listed on the status page.

You still control personal verification

Your agent could request exploration, but you still need the extension and your selected browser tab. You browse the website yourself. You still approve Duo on your phone and complete any other personal verification. After that, your agent checks progress and continues the supported work. Keep passwords and verification codes out of assistant messages.

Recovering an expired sign-in

A saved login can expire. Today, ChatGPT then shows a message that tells you to select Sign in to website in MCParrot, and you sign in again and ask again. The automatic recovery below is aspirational.

You can choose to save a username and password separately for each website app. Enter them only in a private MCParrot form. You can replace or delete them later. The app uses them only for that website and its approved sign-in page. It does not collect passwords while you explore or copy them from your browser.

Browser Use would use saved details to sign in again when your tasks run. You still enter each text code yourself. Your assistant can request a private entry page or check whether details are saved, but it cannot read your password.

  1. The browser attempts sign-in

    If you chose to save your sign-in details securely, Browser Use enters them and continues as far as possible. If not, you enter your sign-in details through a secure page inside our app.

  2. Your assistant shows a verification request

    The tool gives a Verification required status and a link that your assistant can show you.

  3. You complete verification

    Enter a verification code on the secure page, or approve Duo on your phone. Keep passwords and verification codes out of assistant messages.

  4. The task continues

    The browser finishes sign-in, and the app tries to continue the waiting task. Some assistants may need to check the task status before they show the result.

User-managed saved logins remain aspirational. They need private account access and encrypted storage before you can use them. Verification codes are not saved. Deleting saved details will remove them from MCParrot; it will not sign out existing website sessions.

Needs a real school test

The sign-in rules of a school may prevent parts of this flow. Unsupported recovery must show a clear failure instead of opening a visible website browser. We have not tested automatic sign-in or Duo recovery on the website of your school.

Questions that need proof

  • Saved tasks become tools without a test, so we must check that each one works for you.
  • Pages you never visited remain unsupported unless discovered and tested separately.
  • Some pages return a whole document instead of separate data messages, so their tasks need another tested method.
  • Some website messages may work only inside the original browser.
  • A changed website may need another recording.
  • We must measure speed before we say the product is faster.
  • The first milestone only reads information. Actions that change website data need a separate plan.

Our first build milestone

First, you browse a reading page, save one suggested task, sign in once, and ask ChatGPT to run it with different inputs. The order of remaining work lists every later stage and how we know each one is finished.

Make failures useful

Sentry is a service that reports errors and slow steps in an app. MCParrot sends it error reports, the timing of each step (Tracing), short log lines (Logs), screen recordings of the workspace with all text hidden (Session Replay), and the timing of each Cursor Composer and ChatGPT tool call (AI agent monitoring). Logs go through Sentry itself, because the Vercel log forwarding feature needs a paid plan. Sentry never receives passwords, cookies, website answers, or the private link secret. The demonstration should show a real problem that these tools helped us fix.
